# Mobile Integration Guide: Yntra Platform

This document describes how to link and consume the shared Rust core (`yntra-core`) from the native iOS (SwiftUI) and Android (Jetpack Compose) mobile clients.

---

## 1. Native Compilation and Library Output

The Rust core is compiled as a static library for iOS and a dynamic library for Android using `cargo-ndk` or similar toolchains:

*   **iOS Target**: Compiled to a static archive (`.a` / Universal framework) linking to the Xcode project.
*   **Android Target**: Compiled to shared library binary objects (`.so`) placed under `app/src/main/jniLibs/` for target ABIs (`armeabi-v7a`, `arm64-v8a`, `x86`, `x86_64`).

---

## 2. Generating FFI Bindings

The bindings are generated via the `yntra-uniffi-bindgen` executable:

```bash
# Generate Swift wrapper and C header for Xcode
cargo run -p yntra-uniffi-bindgen -- generate --library target/debug/yntra_core.dll --language swift --out-dir generated_bindings

# Generate Kotlin wrapper for Android Studio
cargo run -p yntra-uniffi-bindgen -- generate --library target/debug/yntra_core.dll --language kotlin --out-dir generated_bindings
```

## 3. Reactive UI Integration (Swift / iOS)

To ensure sub-millisecond, zero-delay UI responsiveness on iOS, do not poll database functions. Implement the `DatabaseObserver` callback protocol generated by UniFFI.

### Implementing the Observer in Swift
Convert the UniFFI observer callback into a Swift main-thread callback:

```swift
import Foundation
import yntra_core // Imported from generated framework

class SwiftDbObserver: DatabaseObserver {
    private let onChange: () -> Void
    
    init(onChange: @escaping () -> Void) {
        self.onChange = onChange
    }
    
    func onDatabaseChanged() {
        DispatchQueue.main.async {
            self.onChange()
        }
    }
}
```

### SwiftUI ViewModel Integration
Use a ViewModel that subscribes to observer updates and projects the state:

```swift
import SwiftUI
import yntra_core

class TodoViewModel: ObservableObject {
    @Published var todos: [TodoItem] = []
    @Published var errorMessage: String? = nil
    private var observer: SwiftDbObserver?
    
    init() {
        // 1. Initial Load
        loadTodos()
        
        // 2. Setup reactive observer
        self.observer = SwiftDbObserver { [weak self] in
            self?.loadTodos()
        }
        
        // Register to Rust core
        registerObserver(observer: self.observer!)
    }
    
    func loadTodos() {
        do {
            self.todos = try getTodos()
        } catch {
            self.errorMessage = error.localizedDescription
        }
    }
    
    func addNewTodo(text: String) {
        do {
            _ = try addTodo(text: text) // Core writes to DB and fires observer automatically
        } catch {
            self.errorMessage = error.localizedDescription
        }
    }
}
```

## 4. Reactive UI Integration (Kotlin / Android)

On Android, wrap the UniFFI callback interface using Kotlin StateFlow.

### Implementing the Observer in Kotlin
```kotlin
package com.yntra.app

import android.os.Handler
import android.os.Looper
import uniffi.yntra_core.DatabaseObserver

class KotlinDbObserver(private val onUpdate: () -> Unit) : DatabaseObserver {
    private val mainHandler = Handler(Looper.getMainLooper())
    
    override fun onDatabaseChanged() {
        mainHandler.post {
            onUpdate()
        }
    }
}
```

### ViewModel Integration (Jetpack Compose)
Use a standard Android ViewModel to manage the state flow:

```kotlin
package com.yntra.app

import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewModelScope
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.launch
import uniffi.yntra_core.*

class TodoViewModel : ViewModel() {
    private val _todos = MutableStateFlow<List<TodoItem>>(emptyList())
    val todos: StateFlow<List<TodoItem>> = _todos
    
    private val _errorMessage = MutableStateFlow<String?>(null)
    val errorMessage: StateFlow<String?> = _errorMessage
    
    private val observer = KotlinDbObserver {
        loadTodos()
    }
    
    init {
        loadTodos()
        registerObserver(observer)
    }
    
    private fun loadTodos() {
        try {
            _todos.value = getTodos()
        } catch (e: Exception) {
            _errorMessage.value = e.message
        }
    }
    
    fun addNewTodo(text: String) {
        viewModelScope.launch {
            try {
                addTodo(text) // Core writes to DB and triggers observer
            } catch (e: Exception) {
                _errorMessage.value = e.message
            }
        }
    }
    
    override fun onCleared() {
        super.onCleared()
        // Prevent leaks
        clearObservers()
    }
}

## 5. Security & Memory Management (FFI Boundary)

When passing sensitive user secrets (such as PINs, passwords, or encryption keys) across the UniFFI boundary to `set_session_key()`, developers must manage memory carefully to prevent secret exposure.

### FFI Memory Leakage Risk
While the shared Rust core zeroizes its own buffers immediately after stretching or derivation, the JNI/Swift bridging layer and host language runtimes (JVM heap, Swift heap) can allocate intermediate copies of `String` arguments that Rust cannot access or clear.

### Recommended Guidelines
1. **Wipe Native Memory**: In Swift or Kotlin, do not store plain-text passwords or PINs in persistent heap variables or long-lived Model/State objects.
2. **Clear UI Buffers**: Securely clear memory buffers of text inputs or custom PIN views immediately after passing the value to the FFI layer.
3. **Use Platform Secure Storage**: Store master session tokens or keys in native secure containers (e.g. Android Keystore, iOS Keychain) rather than keeping them in memory.
```
